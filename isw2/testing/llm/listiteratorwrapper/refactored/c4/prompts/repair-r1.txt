# ListIteratorWrapper C4 / T_LLM — Repair R1

La suite T_LLM generata per:

org.apache.openjpa.lib.util.collections.ListIteratorWrapper

contiene esattamente 12 scenari TLLM-001 ... TLLM-012.

La prima validazione runtime ha prodotto i seguenti problemi:

- TLLM-002: `hasPrevious()` termina con `UnsupportedOperationException`
- TLLM-003: `hasPrevious()` termina con `UnsupportedOperationException`
- TLLM-004: `previous()` genera `UnsupportedOperationException` invece di `NoSuchElementException`
- TLLM-005: `previous()` termina con `UnsupportedOperationException`
- TLLM-006: `reset()` termina con `UnsupportedOperationException`
- TLLM-008: l'eccezione di `add()` / `set()` non ha il messaggio atteso

Dallo stack trace risulta che i setup basati su:

`List.of(...).iterator()`

stanno producendo a runtime un oggetto della famiglia `ImmutableCollections$ListItr`, che viene quindi trattato dal production code come `ListIterator` invece che come semplice `Iterator`.

Correggi esclusivamente questo problema tecnico di setup.

- Non usare altre suite di test o fonti esterne.
