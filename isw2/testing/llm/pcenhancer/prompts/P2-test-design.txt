# P2 - Test Design

Continua lo stesso esperimento su:

org.apache.openjpa.enhance.PCEnhancer
Apache OpenJPA 4.1.1

Usa esclusivamente:
- il production context fornito;
- l'analisi prodotta nella fase P1;
- eventuali classi production aggiunte esplicitamente dopo P1.

Non utilizzare:
- test nativi OpenJPA;
- T_BB, T_CF, T_MT, T_RND o T_ES;
- risultati JaCoCo;
- risultati PIT;
- survivor mutation;
- Web o fonti esterne.

Progetta esattamente 30 test case/scenari distinti per PCEnhancer, identificati:

TLLM-001 ... TLLM-030

Non scrivere ancora codice Java.

Per ogni caso indica:
- ID;
- comportamento considerato;
- input e setup necessari;
- azione da eseguire;
- risultato atteso o altro elemento osservabile.

Il conteggio `N = 30` riguarda i test case/scenari, non il numero futuro di
metodi Java o di helper.

Se un caso richiede informazioni production non disponibili, non inventare API
o comportamenti: segnala precisamente ciò che manca.

Alla fine conferma:
- numero totale dei test case = 30;
- presenza degli ID da TLLM-001 a TLLM-030 senza salti;
- eventuali dipendenze production ancora mancanti.
